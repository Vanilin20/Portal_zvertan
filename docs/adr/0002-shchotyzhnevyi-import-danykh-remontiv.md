# ADR-0002: Щотижневий пакетний імпорт даних ремонтів замість інтеграції в реальному часі

Статус: прийнято
Дата: 2026-11-25

## Контекст

Мешканці хочуть бачити ремонти доріг на карті «онлайн» (User Story 5 — водій об'їжджає перекриті дороги). Проте підрядник з ремонту доріг не має власного API і готовий передавати дані лише раз на тиждень, «без зайвого бюрократизму» (реєстр стейкхолдерів). Формат файлу ще не узгоджено (відкрите питання № 3: Excel, JSON чи вручну). Інтеграція в реальному часі вимагала б від підрядника розробки сервісу, якого він не має, а від нас — постійного з'єднання та обробки збоїв зовнішньої системи.

## Рішення

Дані про ремонти надходять пакетно: раз на тиждень підрядник (або працівник ради від його імені) завантажує файл через модуль імпорту (FR-08). Система перевіряє кожен рядок, імпортує коректні, формує звіт про відхилені рядки й оновлює карту (FR-07). На карті показується дата останнього імпорту, щоб користувач розумів актуальність даних. Модуль імпорту будується навколо одного адаптера формату, щоб після відповіді на відкрите питання № 3 змінювати лише його.

## Наслідки

**Переваги:**
- підряднику не потрібно нічого розробляти — достатньо вивантажити таблицю;
- немає залежності від доступності зовнішнього сервісу — збій у підрядника не впливає на uptime порталу (NFR-R-001);
- критерій FR-08 стає перевірюваним: ≥95% коректних рядків імпортуються, карта оновлюється протягом 1 години;
- простіша реалізація й тестування в межах 8-тижневого MVP.

**Компроміси й обмеження:**
- дані на карті можуть відставати від реальності до 7 днів — водій може не побачити ремонт, що почався вчора;
- якість карти повністю залежить від того, чи вчасно й без помилок підрядник надішле файл;
- поки формат файлу не узгоджено, адаптер імпорту реалізується «під припущення» і може потребувати переробки;
- якщо в майбутньому підрядник надасть API, перехід на синхронізацію в реальному часі оформлюється новим ADR, що замінить цей.
