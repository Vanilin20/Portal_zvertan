# Фази життєвого циклу та дорожня карта

Для MVP тривалістю 8 тижнів визначено шість основних фаз. Завершення кожної фази означає отримання перевірюваного артефакту перед переходом до наступної.

## Фази

| Фаза | Зміст | Тривалість | Артефакти |
| --- | --- | --- | --- |
| 1. Аналіз вимог | Уточнення FR/NFR, перевірка Use Case і критеріїв прийнятності | 1 тиждень | ТЗ v1.0, Use Case, User Stories, backlog вимог |
| 2. Проєктування | Архітектура, БД, основні екрани | 1 тиждень | ERD, UML-діаграми, wireframes, архітектурна схема |
| 3. Розробка | Подання звернення, ідентифікація, кабінет, адмінпанель | 3 тижні | Вихідний код, юніт-тести, записи Code Review, CI-збірка |
| 4. Тестування | Функціональна, інтеграційна, навантажувальна, перевірка доступності | 1 тиждень | Test Plan, Test Report, Buglist, Acceptance Report |
| 5. Розгортання | Підготовка MVP та розгортання на тестовому середовищі | 1 тиждень | Release Notes, CI/CD pipeline, робочий build |
| 6. Супровід | Виправлення дефектів, підготовка оновлень після релізу | після релізу | Changelog, патчі, звіти про інциденти, план підтримки |

## Roadmap

| Тиждень | Заплановані роботи | Результат |
| --- | --- | --- |
| 1 | Аналіз вимог | Узгоджений backlog і ТЗ |
| 2 | Проєктування | ERD, UML, wireframes, архітектура |
| 3 | Розробка: FR-01, FR-02 | Форма звернення та е-ідентифікація |
| 4 | Розробка: FR-03, FR-05 | Особистий кабінет і фільтрація звернень |
| 5 | Розробка: FR-06, FR-10 | Відповіді працівника та квартальний звіт |
| 6 | Тестування | Test Report, Buglist, Acceptance Report |
| 7 | Розгортання | MVP на тестовому середовищі, Release Notes |
| 8 | Стабілізація та підготовка релізу | Готовий MVP і користувацька документація |
