# Вибір моделі SDLC

Проєкт: «Портал звернень громадян» (Варіант 5 — Міська рада). Основа — ТЗ з Практичного заняття № 2.

## Картка проєкту

| Поле | Значення |
| --- | --- |
| Назва проєкту | Портал звернень громадян |
| Тип системи | Web |
| Замовник | Міська рада (умовний замовник навчального завдання) |
| Розмір команди | Індивідуальний проєкт; виконавець — Оліферук Іван |
| Очікуваний термін | 8 тижнів на реалізацію MVP |
| Стабільність вимог | Переважно стабільні; основний пакет вимог формалізований у ТЗ |

## Оцінка критеріїв

| Критерій проєкту | Відповідь | Орієнтовна модель SDLC | Пов'язаний метод |
| --- | --- | --- | --- |
| Вимоги стабільні, замовник — міська рада | Основні вимоги вже зібрані та формалізовані | Waterfall | Структурні |
| Потрібна формальна перевірка | Є критерії прийнятності, NFR та Definition of Done | V-модель | Формальні |
| Вимоги уточнюються ітераційно | Можливі уточнення відкритих питань, але ядро вимог сформоване | Ітераційна (RUP) | Об'єктно-орієнтовані |
| Високі ризики, інноваційність | Проєкт не є високоризиковим інноваційним продуктом | Спіральна — менш доречна | Універсальна |
| Невелика команда, регулярні релізи | Індивідуальний проєкт, поступове виконання задач | Kanban | Agile |

## Обрана модель

**Waterfall із використанням Kanban-дошки для організації щоденної роботи.**

Замовник — міська рада, а вимоги вже зібрані та оформлені у ТЗ. Проєкт має ознаки послідовної розробки й орієнтується на один реліз MVP. Формальний характер вимог до персональних даних, ідентифікації та доступності також підтримує послідовний підхід. Kanban використовується як інструмент керування конкретними задачами всередині етапів, тому не змінює основну модель життєвого циклу.
