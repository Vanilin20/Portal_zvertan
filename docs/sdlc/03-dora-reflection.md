# DORA-рефлексія

**Deployment Frequency.** Поділ роботи на невеликі задачі та короткі ітерації не дає накопичувати великі пакети змін. Перевірені задачі можуть потрапляти до релізної збірки, що створює основу для регулярних розгортань.

**Lead Time for Changes.** Kanban-дошка показує поточний стан кожної задачі й прибирає невизначеність щодо її етапу. Розбиття вимог FR на задачі з оцінкою часу скорочує шлях від постановки задачі до готового результату.

**Change Failure Rate.** Перед переміщенням задачі в Done передбачені Code Review, автоматизовані тести та ручна перевірка критерію прийнятності. Definition of Done вимагає відсутності критичних дефектів, тому ризик потрапляння некоректної зміни до релізу зменшується.

**MTTR.** Buglist, Git-історія та зрозумілі статуси Kanban допомагають швидко визначити проблемну зміну. Окремі задачі на виправлення дефектів і підготовлений процес розгортання спрощують повернення системи до працездатного стану.
