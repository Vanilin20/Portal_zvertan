# Портал звернень громадян

Вебсистема для мешканців міста та працівників міської ради: громадянин після е-ідентифікації подає звернення онлайн і стежить за його статусом, а працівник ради обробляє звернення у власній панелі. Навчальний проєкт (Варіант 5 — Міська рада), зараз на етапі **проєктування** — коду ще немає, у репозиторії зберігаються вимоги, архітектурні рішення, діаграми та прототип.

## Можливості

- Подання звернення через веб-форму: категорія, опис, адреса, фото (FR-01).
- Обов'язкова авторизація через державний сервіс е-ідентифікації — анонімні звернення не приймаються (FR-02, DOM-01).
- Особистий кабінет зі статусом звернення та email/push-сповіщеннями про зміни (FR-03, FR-04).
- Панель працівника ради: фільтр звернень за категорією й статусом, офіційна відповідь (FR-05, FR-06).
- Інтерактивна карта ремонтів доріг зі щотижневим імпортом даних підрядника (FR-07, FR-08).
- Новини міста за категоріями та квартальний звіт для депутатів у PDF/Excel (FR-09, FR-10).
- Доступність інтерфейсу за WCAG 2.1 AA, шифрування персональних даних AES-256.

## Встановлення / запуск

Програмного коду поки немає (фаза «Проєктування», див. [дорожню карту](docs/sdlc/02-phases-roadmap.md)). Щоб отримати робочу копію документації та прототипу:

```bash
git clone https://github.com/Vanilin20/Portal_zvertan.git
cd Portal_zvertan
```

Залежностей і змінних середовища не потрібно. Markdown-файли зручно переглядати на GitHub або в будь-якій IDE з Markdown-переглядом.

## Приклад використання

Пройти основний сценарій «Подати звернення» на каркасному прототипі:

1. Відкрийте у браузері `docs/prototype/index.html`.
2. Натисніть «Подати звернення» → «Увійти через е-ідентифікацію».
3. Заповніть форму й натисніть «Надіслати» — з'явиться екран із номером звернення, далі — особистий кабінет зі статусом.

Той самий сценарій описано діаграмами: [діяльності](docs/diagrams/activity.png) і [послідовності](docs/diagrams/sequence.png). Інтерактивний прототип у Figma: _посилання буде додано_.

## Як зробити внесок

1. Створіть гілку від `main`: `git checkout -b docs/<коротка-назва>`.
2. Пишіть коміти у форматі `docs: <що змінено>` / `feat: <що додано>`.
3. Відкрийте pull request і прив'яжіть його до задачі з [дошки](docs/board/sprint-plan.md).
4. Нове архітектурне рішення оформлюйте окремим файлом у `docs/adr/` з наступним номером; прийняті ADR не редагуються — їх замінює новий ADR.
